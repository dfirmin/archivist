# Live proof — 2026-10-07: the Pi harness (ADR 0008)

Environment: Claude Code cloud workspace, run natively from branch `feat/pi-harness` with
`--engine current`. Pi `@earendil-works/pi-coding-agent` 1.0.4 in `anthropic-api` mode (and one
run in `gateway-key` mode, below); Claude Code 2.1.292 in `inherit` mode. Both harnesses ran the
same engine commit on fresh `load-target` copies of the same target, side by side, with
`--skip-publish` (the machine was idle: load average 0.3 on 2 CPUs, so running both at once did
not skew timing). Agents pin their own models: Sonnet 5.5 for conductor, planner, extractor,
author and verifier; Haiku 4.5 for gap-agent and scorer.

Baselines: the publishing runs already on the test targets, from Claude Code, before this branch:
`archivist-knowledge-example` PR #2 (`archivist/run-20261006T013958Z`) and
`archivist-knowledge-01` PR #18 (`archivist/run-20261005T232925Z`).

## Full inbox: `archivist-knowledge-example`, pipeline `no-code` (17 documents, 3 transcripts)

| Run | Harness | Sessions | Wall clock | Cost (reported) |
|---|---|---|---|---|
| cc-1 | Claude Code | 12 | 1,178 s | $5.98 |
| pi-1 | Pi, Haiku thinking off, Sonnet on a fixed 8,192-token budget | 11 | 1,303 s | $2.83 |
| cc-2 | Claude Code | 12 | 1,250 s | $5.74 |
| pi-2 | Pi, Haiku thinking off, Sonnet adaptive | 12 | 1,247 s | $2.94 |

Outcomes, all four runs and the baseline: the same 12 concept files (8 authored, 4 View
companions), the same 5 quarantined (the legacy-feed extract and email, the small-talk transcript,
BR-CLM-031, policy churn), BR-HOM-022's amendment held in the inbox. Every transcript extracted to
the same topics. Confidence scores drift run to run on both harnesses (CLAIM_PMT_SV: baseline 0.3,
cc 0.60/0.62, pi 0.60/0.65).

**Speed: no gain.** Wall clock is a tie (cc-2 and pi-2 ran side by side: 1,250 s and 1,247 s;
Claude Code alone varied 1,178–1,250 s). Session time is model turns, and the harness does not
change the turns: turn for turn, a Pi sub-agent and a Claude Code one make the same calls. Pi's
process start is about 0.6 s per spawn (measured against the scripted endpoint).

**Cost: about half.** Cache reads 4.7 M tokens on Pi against 12.8 M on Claude Code, because Pi's
system prompt and tool set are a fraction of Claude Code's. Both Pi runs had Haiku's thinking
off (pi-1 also gave Sonnet a fixed budget on every turn, which slowed each Sonnet sub-agent; pi-2
has it adaptive, as Claude Code). Matching Haiku's thinking (below) adds thinking tokens to every
gap-agent and scorer turn; the full-run cost with it is not yet measured.

## Gap verdicts: the one quality difference, found and fixed

Against the baseline, Pi's runs missed present gaps that Claude Code found (pi-1: 1, pi-2: 3;
cc-1: 0, cc-2: 0 missed and 1 extra). Pi's Haiku called "LOB_CD: AUTO, HOME, COMM (line of
business)" fully documented, and "CRM extract" a mention of the registered "Sample CRM". Claude
Code's verdicts were the correct ones under the contract.

A repeated test isolated it: Claude Code run 2's two business-view overviews, `okfx_gaps` cleared,
`--pipeline gaps --kind undefined_acronym,missing_code_value_semantics,unregistered_source_system`
(6 judgements per run; truth = where the baseline and both Claude Code runs agree), five runs
per configuration.

| Configuration | Correct of 30 | Mean run time |
|---|---|---|
| Claude Code | 30 | 274 s |
| Pi, Haiku thinking off | 24 (and twice wrote a kind it was not asked for) | 195 s |
| Pi, Haiku thinking off, engine base prompt instead of Pi's preamble | 22 | 182 s |
| Pi, Haiku budgeted 31,999, Pi's preamble | 30 | 309 s |
| Pi, Haiku budgeted 31,999, engine base prompt | 29 | 323 s |
| **Pi, final** (budgeted 31,999, thinking display omitted) | **29** | **254 s** |
| Claude Code, same round as the final | 28 | 243 s |

The cause, from the requests themselves (a logging proxy in front of `api.anthropic.com`, one
judgement run per harness): Claude Code sends Haiku sub-agents `thinking: {type: enabled,
budget_tokens: 31999, display: omitted}` and Sonnet `thinking: {type: adaptive}` at `effort:
medium`. *Omitted* is why its transcripts show no thinking blocks, which first read as "no
thinking". Pi now sends the same: adaptive thinking for 5.x models (`compat.forceAdaptiveThinking`
in `models.json`), budgeted 31,999 for the rest (`thinkingBudgets`), display omitted (the
extension). The engine base prompt had no measurable effect and was dropped (AGENTS.md: no
addition without a live failure that needs it).

Over ten runs each with Claude Code's thinking budget (the last two Pi rows with Pi's
preamble: display summarized, then omitted), Pi 59 of 60, Claude Code 58 of 60. The misses on
both are Haiku's own variance on borderline wording.

## Defect found and fixed

- **Pi's `find` tool had no `fd`.** Pi downloads `fd` on first use; the network allowlist (and an
  air-gapped container) blocks it, so `find` failed and the agent fell back to `bash find`,
  costing a turn. The image now installs `fd-find` and `ripgrep`, which Pi uses as found.

## Not proven yet

- Publishing on Pi (branch, PR, issues, re-run without duplicates), and `local-claude` mode.
- A full-inbox run of the final configuration end to end: its cost with Haiku thinking.
- `kb-pi` to the end.

All three wait on API credit.

# Live proof — 2026-10-07 (later): contracts preloaded and groups in parallel (ADR 0009)

Same environment; engine `feat/pi-harness` at `99028ac`, `--engine current`, `--parallel 3`,
contract preload on. Pi in `anthropic-api` mode with the final thinking settings; Claude Code in
`inherit` mode. Fresh `load-target` copies.

| Run | Harness | Publish | Rounds | Wall clock | Pi cost |
|---|---|---|---|---|---|
| example, first try | Claude Code | no | 3 | 473 s | — |
| example | Claude Code | no | 3 | 460 s | — |
| example | Pi | **yes**: PR #23 on the mirror | 3 | 864 s (stages 446 s; finishing with 11 commits and issues 276 s) | $2.90 |
| knowledge-01 | Claude Code | no | 3 | 373 s | — |
| knowledge-01 | Pi | no | 3 | 431 s | $1.56 |

Serial runs of the same inboxes took 1,178–1,250 s (example) and 829 s (knowledge-01): about
2.6× and 2.2× faster on Claude Code. A full example run on Pi cost $2.90 with Haiku's thinking
matched and the preload on, against $2.83–2.94 serially with Haiku's thinking off.

Each round: the planner once, extraction alone (round 1), the remaining groups three at a time,
one finishing session. The warehouse amendment (BR-HOM-022, no primary in the inbox) was left in
round 2, planned again in round 3, left again and held, as designed.

## Outputs

Every run, both targets: the same concepts at the same paths, the same quarantined drafts, the
same held document as the serial runs and the baselines. Gap verdicts equal to the baseline on
every concept of both targets, both harnesses. Titles differ only where the target's naming rule
allows either (`Expense Reimbursement` / `… Policy`, `Travel Booking` / `… Policy`; Claude Code
varies the same way between its own runs).

**Blind review.** A separate reviewer read every authored concept of three runs against their
cited sources and the contracts, labelled A/B/C without knowing which was which (A = Pi on this
engine, B = Claude Code on this engine, C = the baseline from the serial engine).

- Example mirror (8 concepts each): no grounding or correctness defect in any run; every
  correction (loss-ratio denominator, open-claim window, total-loss threshold) stated at its
  current value. Ranking A ≥ C ≈ B. B dropped the required `Business Rules & Usage Notes`
  heading from two view overviews; A filled two Source sections the others stubbed.
- Knowledge-01 (7 concepts each): equivalent. Corrections current in all ($75 meals, 15-minute
  DBA page, five business days). Small slips spread across runs: A left the test page out of
  the handoff steps (kept under Verification); B cited the $75 rule to a source that says $60.

The dropped heading is older author variance, not this engine or harness: serial runs dropped
it too (Claude Code 2 of 3 view overviews in one run, Pi 1 of 3 in another). The gap fleet
records it as `missing_section` every time. Repeated live, it is now a candidate for a
`check-concept` rule (required headings present).

## Defects found and fixed

- **Preloaded registries leaked into a title.** First Claude Code run: a view whose source has
  no business name was titled "Claim Payment" from the naming standards (`PMT` = payment),
  against the intake rule and five earlier runs (`CLAIM_PMT_SV`). The preload header now
  restates that reference data answers lookups and never becomes a title, name or body text.
  Every later run, both harnesses: `CLAIM_PMT_SV`.

## Observed

  session, then the finishing session's one commit per group (11 commits), gap issues #6–#17
  and quarantine issues updated in place, no duplicates left open. The extraction session
  created a duplicate of quarantine issue #20 as #24 before searching, found #20, updated it and
  closed #24 as not planned: the skill says find first, then create.
- A sub-agent's progress lines on Pi (written by the extension to stderr) carry no session
  label in parallel output; cosmetic.
